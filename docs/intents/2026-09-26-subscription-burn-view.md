# 구독 지출과 한도 소진 전망

## 사용자 요청

지금 이 구독을 통해 월에 얼마 정도 지출이 되는지 보고 싶다.
Claude Code·Codex·agy·Grok 각각 이대로 주간 세션을 다 사용할 수 있을지, 많이 남을지 계산해서 보여줘야 한다.
구독을 더 할지 취소할지 의사결정을 하기 위한 것이다. 사용량이 적당한지 부족한지 많은지 보기 위함이다.

주간 사용률 기준으로 100%를 다 쓰는 것을 목표로 한다.

## 브레인스토밍에서 확정한 것

- 단가는 서비스별 단가표에 사람이 적고, 계정 수는 프록시에서 읽어 곱한다.
- 이력을 오늘부터 쌓되, 이력이 없는 동안은 현재 주기 외삽으로 보여주고 추정임을 표시한다.
- 화면은 "지출" 블록과 "소진" 블록으로 분리한다.
- 대시보드 맨 위, 한 줄 요약 밴드 아래에 새 섹션으로 둔다.

## 범위

메뉴바 대시보드에 섹션 하나를 더한다. 이력 저장은 이미 도는 60초 폴링에 얹고 새 프로세스를 만들지 않는다.

범위 밖: 결제·청구 연동, 계정 자동 생성·해지, 프록시 저장소 수정, 사용량을 조절하는 자동 동작.

## 영향

- 대시보드 높이가 약 240pt 늘어난다(1170 → 약 1410pt).
- 새 파일 두 개가 생긴다: 이력(`~/.codex/cache/cc-menubar-quota-history-v1.json`), 단가 설정(`~/.config/cc-menubar-subscriptions.json`).
- 단가를 입력하기 전에는 지출 블록이 `미입력`으로 동작한다. 소진 블록은 단가와 무관하게 완전히 동작한다.

## 제약

- 금액을 추정하지 않는다. 단가가 없으면 `미입력`이다.
- 목표 100%의 대가를 숨기지 않는다. 평균이 100%면 평균을 넘는 주에는 막히므로, 이력이 쌓이면 최소~최대 범위를 함께 보인다.
- 기여하지 않는 계정(오류·비활성)을 지출과 분리해 보인다. 고칠 수 있는 문제에 돈을 쓰게 되는 것을 막기 위해서다.

## 열린 질문

- 계정별 요금제가 섞여 있으면 서비스 단가 하나를 곱한 합계가 틀린다. 필요해지면 계정별 예외를 덮어쓰는 방식을 얹는다.
- Grok은 리셋 시각을 주지 않아 이력으로 주기 경계를 역산해야 한다. 확정 전에는 전망을 내지 않는다.
